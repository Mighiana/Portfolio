SplitSmart

Local-first Flutter expense app with group balances, budgets and saving goals, encrypted SQLite storage and Firebase synchronization for signed-in users.

Android beta · Invite-only internal testing

  • Flutter / Dart
  • Firebase Auth
  • Firestore
  • SQLite / SQLCipher
  • Provider

Technical evidence chain

  1. Group expenses
  2. →Balance engine
  3. →Local state
  4. →Firebase sync

App name: Splitzee · No public release.

Problem
Shared expenses need stable per-member balances without making everyday entry depend on network availability.
What I built
Splitzee: group expense splitting and settlements, wallets, budgets, saving goals, subscriptions and reminders, with multi-currency data and authentication.
Architecture
Flutter / Provider → AppState → encrypted SQLite; background Firestore sync for signed-in users. Firebase Auth separates local, anonymous guest and full account tiers.
Implementation
Stable member-ID balance calculations, equal/percentage/share/custom splits, local-first writes, SQLCipher with device-held keys and membership-scoped Firestore rules.
Technical decisions
Subscriptions and scheduled notifications stay local; reminders and other supported data sync for signed-in users. Local storage remains primary and Firestore rules enforce cloud access.
Status / limitations
Android beta on Google Play internal testing, not publicly released. Cloud Functions/Storage are not deployed and iOS is not configured. No claim of a public production demo.
