P—02 / Cloud security / Application security / AWS / 2025 → 2026

Secure Cloud File Management Platform

Quarantines uploads until integrity, file-signature and optional ClamAV checks pass, with per-user access, least-privilege S3 storage and tamper-evident auditing.

Working / locally verified

  • ASP.NET Core 8
  • SQL Server
  • Amazon S3
  • Terraform
  • ClamAV
  • LocalStack
  • Docker

Technical evidence chain

  1. Untrusted upload
  2. →Quarantine
  3. →Validation
  4. →Approved / rejected
  5. →Controlled download

Rejected or quarantined files remain blocked.

Problem
Cloud storage should not turn an untrusted upload into a downloadable file. Authorization, validation and audit evidence must survive failures.
What I built
An ASP.NET Core 8 file portal with Admin / User roles, per-user ownership, private quarantine and approved S3 buckets, and a hash-chained application audit log.
Architecture
Authenticated Razor/MVC application → SQL Server metadata and audit chain → quarantine S3 → validation worker → approved S3. Short-lived pre-signed URLs allow authorized downloads.
Implementation
SHA-256 re-hashing, magic-byte validation, optional ClamAV and fail-closed scanner behavior. Terraform defines storage/IAM; Docker uses LocalStack, SQL Server and ClamAV. Automated .NET, Lambda and infrastructure tests run in CI.
Technical decisions
Authenticated-by-default and least-privilege IAM. Application audit records user/security actions; CloudTrail records AWS API activity. The audit chain detects tampering but has no external anchor. No GuardDuty dependency.
Status / limitations
Original November 2025 coursework; validation pipeline and reproducibility added in 2026. Working local Docker evidence, not a public production service. Terraform/Lambda have not been deployed to real AWS from this repository; scanner limits, no MFA and shared worker permissions remain.
